# XDriver CAN 协议

> 固件实现：`FOC/UserApp/protocols/interface_can.c`（`can_protocol_on_cmd()`）
> 上游来源：Dummy-Robot `Ctrl-Step-Driver` 的 `interface_can.cpp` + `Core/Src/can.c`
> 适用固件：本仓库当前 `main`（节点号、命令表以本文为准）
> 硬件：CAN1，PB8=RX / PB9=TX（重映射 2），**1 Mbit/s**，无终端电阻以外的额外要求

---

## 1. 帧格式

| 项 | 值 |
|---|---|
| 帧类型 | 标准数据帧（IDE = STD，RTR = DATA） |
| 速率 | 1 Mbit/s（Prescaler 4，BS1 5TQ，BS2 3TQ；APB1 = 72 MHz / 2 = 36 MHz，9 TQ × 111 ns = 1 µs） |
| DLC | 命令帧 0~8；**应答帧固定 8** |
| ID 布局 | `StdId = (node << 7) \| cmd`，node 占高 4 bit（0~15），cmd 占低 7 bit（0x01~0x7F） |
| 字节序 | 小端（float32 / int32 均直接 `memcpy`，无字节交换） |
| 浮点格式 | IEEE-754 binary32 |

### 1.1 节点号

| node | 含义 |
|---|---|
| 0 | **广播**：总线上所有节点号为 0 的驱动器都会执行，应答也用 0 号 ID |
| 1~15 | 单播：节点号匹配的驱动器执行 |

- 默认节点号来自启动时按 MCU 唯一 ID 查表（只覆盖原厂 6 块板），查不到则为 **0**。
- 设置方法：`xdrv node <id>`，或 CAN 命令 `0x11`。见 §3.2。
- 节点号 0 的板**会接受所有广播帧**，多板同总线调试时务必先改成各自节点号。

### 1.2 ID 速查

```
base = node << 7            (= node × 128)

主机 -> 驱动器：base | cmd     cmd = 0x01 ~ 0x7F
驱动器 -> 主机：base | 0x21..0x24
```

以 **node = 3** 为例：

| 用途 | StdId | 说明 |
|---|---|---|
| `base` | `0x180` | 仅用于拼 ID，**总线上不存在 cmd=0 的帧** |
| 命令帧 | `0x181` ~ `0x1FF` | `base \| 0x01..0x7F` |
| 应答帧 | `0x1A1` ~ `0x1A4` | `base \| 0x21..0x24` |

`xdrv node` 会直接打印 `base id / rx id / tx id`，不用手算。

### 1.3 接收过滤

硬件过滤器是**全通**（`CAN_FILTERMODE_IDMASK`，32 bit，mask = 0，进 FIFO0），
节点号在软件里比对：`node == 0 || node == boardConfig.can_node_id`。
因此：

- 总线上所有帧都会进硬件邮箱（分析仪上看得到），但只有节点号匹配的命令才执行；
- 节点号不匹配的帧计入 `xdrv status` 的 `can other=`；
- 扩展帧（IDE=EXT）的 `StdId` 为 0，会被当成 node 0 / cmd 0 而忽略。

## 2. 命令总表

### 2.1 `0x00`~`0x0F` 实时控制（不落 Flash）

| cmd | 名称 | 数据（data[0..7]） | 单位/说明 | 应答 |
|---|---|---|---|---|
| `0x01` | 使能 | `uint32 en` | `1` = 进入速度模式并使能；其它值 = 停止（idle，功率级休眠） | — |
| `0x02` | 触发编码器校准 | — | 约数秒，电机会自动转两圈，**要求轴可自由转动** | — |
| `0x03` | 电流设定值 | `float i` | A，内部换算成 mA 并限幅到 rated_current | — |
| `0x04` | 速度设定值 | `float v` | r/s，内部 ×51200 转成 steps/s | — |
| `0x05` | 位置设定值 | `float p` + `data[4]` | r（圈），`data[4]≠0` 时要求应答 | `0x23`（条件） |
| `0x06` | 位置 + 到达时间 | `float p` + `float t` | r、s；`data[4]` 同时是应答请求（见 §4.2） | `0x23`（条件） |
| `0x07` | 位置 + 限速 | `float p` + `float vmax` | r、r/s；速度上限写进 `rated_velocity` | `0x23`（总是） |

- `0x03`~`0x07` 会自动切换到对应模式；`0x01`/`0x03`~`0x07` 都会**清除 `soft_disable`/`soft_brake`**（等价于 msh 的 `xdrv on` 效果），否则先 `off` 过的板子收到命令会"生效但不动"。
- `0x05`/`0x07` 在切换模式时先把 `rated_velocity` 恢复成 `boardConfig.velocity_limit`，随后 `0x07` 再用命令里的限速覆盖它；`0x06` 不重设限速（与上游一致）。
- 未完成编码器校准（`xdrv status` 显示 `calib: NO`）时功率级始终休眠，任何运动命令都不会出力。

### 2.2 `0x10`~`0x1F` 参数（可落 Flash）

`data[4] != 0` 表示**同时把该参数写入 Flash 配置页**（否则只改 RAM，掉电丢失）。
`0x15` 例外：它总会落盘。

| cmd | 名称 | 数据 | 单位/说明 |
|---|---|---|---|
| `0x11` | 设置节点号 | `uint32 node` | 0~15，立即生效（软件过滤），见 §3.2 |
| `0x12` | 限流 | `float A` | 写入 `rated_current`（mA）与 `boardConfig.current_limit` |
| `0x13` | 限速 | `float r/s` | 写入 `rated_velocity` 与 `boardConfig.velocity_limit` |
| `0x14` | 加速度 | `float r/s²` | 同时更新 velocity/position tracker 的加速度 |
| `0x15` | 应用当前点为零点 | — | 总是落盘；等价于 `xdrv home` |
| `0x16` | 上电自使能 | `uint32 en` | `1` = 使能（仅记录在配置里） |
| `0x17` | DCE Kp | `int32` | 位置环比例（原始整数，非物理单位） |
| `0x18` | DCE Kv | `int32` | 速度反馈系数 |
| `0x19` | DCE Ki | `int32` | 积分（内部放大 1024 倍） |
| `0x1A` | DCE Kd | `int32` | 微分 |
| `0x1B` | 堵转保护 | `uint32 en` | `1` = 开启 |

> 落盘采用"延迟写"：只置 `CONFIG_COMMIT`，由 100 Hz 线程在**电机停止**
> （`mode_running == STOP` 或 `soft_disable`）后才真正擦写 Flash。
> 运动中下发的保存命令不会丢，但会等到停机那一刻才写入。

### 2.3 `0x20`~`0x2F` 查询（总是应答）

| cmd | 名称 | 应答 ID | 应答 data[0..3] | data[4] |
|---|---|---|---|---|
| `0x21` | 读电流 | `base \| 0x21` | `float` **A**（FOC 电流，1 mA 分辨率） | 到位标志 |
| `0x22` | 读速度 | `base \| 0x22` | `float` **r/s**（估算速度） | 到位标志 |
| `0x23` | 读位置 | `base \| 0x23` | `float` 圈（含 home offset） | 到位标志 |
| `0x24` | 读零点偏移 | `base \| 0x24` | `int32` steps（1 圈 = 51200） | — |

到位标志：`1` = `state == MOTOR_STATE_FINISH`，其它状态为 `0`。
应答帧 `data[5..7]` 是请求帧对应字节的回显，无意义。

### 2.4 `0x7E` / `0x7F`

| cmd | 名称 | 行为 |
|---|---|---|
| `0x7E` | 擦除配置 | 置 `CONFIG_RESTORE`：停机后把当前配置写回并**复位**；上电校验失败 → 恢复出厂值（节点号一起丢） |
| `0x7F` | 复位 | 立即 `HAL_NVIC_SystemReset()` |

## 3. 典型报文

以下均以 **node = 3**（`base = 0x180`）为例，数据为十六进制。

### 3.1 使能 + 速度控制

| 步骤 | StdId | DLC | Data | 说明 |
|---|---|---|---|---|
| 使能 | `0x181` | 4 | `01 00 00 00` | 进入速度模式，设定点沿用上一次 |
| 1 r/s | `0x184` | 4 | `00 00 80 3F` | `1.0f` |
| 停止 | `0x181` | 4 | `00 00 00 00` | 非 1 → `MODE_STOP` |

### 3.2 设置节点号（广播帧）

板子刚换、节点号还是 0 时，用广播 ID 一次性设好：

| StdId | DLC | Data | 说明 |
|---|---|---|---|
| `0x011` | 5~8 | `03 00 00 00 01` | 节点号 = 3，`data[4]=1` → 落盘 |

之后 `xdrv node` 应显示 `node: 3`、`base id: 0x180`；重启后仍是 3。
> 板子必须**单独**上总线：此时它接受所有广播帧，同总线上还有别的 0 号板会一起被改。

### 3.3 位置 + 应答

| 步骤 | StdId | DLC | Data |
|---|---|---|---|
| 走到 -0.5 圈并要求应答 | `0x185` | 5 | `00 00 00 BF 01`（`-0.5f` + `data[4]=1`） |
| 应答（当前位置） | `0x1A3` | 8 | `00 00 00 BF 00 ..`（-0.5f，`data[4]=0` 表示未到位） |

### 3.4 设限流 1.2 A 并保存

| StdId | DLC | Data |
|---|---|---|
| `0x192` | 5 | `9A 99 99 3F 01`（`1.2f` + `data[4]=1`） |

若此时电机正在出力，Flash 写入会推迟到 `xdrv off` / 停机后；可用 `xdrv status`
的 `cfg : limit=` 确认 RAM 值已生效。

## 4. 语义细节

### 4.1 应答规则

- `0x21`~`0x24`：**总是**应答。
- `0x07`：**总是**应答（带位置 + 到位标志）。
- `0x05` / `0x06`：`data[4] != 0` 时才应答。
- 其余命令不应答。应答 ID 使用**本机节点号**（即使请求是广播帧，回复仍用自身 node）。

### 4.2 `0x06` 的应答标志与时间浮点重叠（上游原始设计）

`0x06` 的时间在 `data[4..7]`，而应答请求正好读的是 `data[4]` —— 也就是**时间浮点的
最低字节**：

- 时间取 1.0 s / 1.5 s / 2.0 s 等"整"值时，最低字节为 `0x00` → **不应答**；
- 时间带零碎尾数（如 0.7 s = `33 33 33 3F`）时最低字节非 0 → **应答**。

这是上游行为，本移植原样保留。需要确定性的应答请用 `0x05`（显式 `data[4]`）或
`0x07`（总是应答）。

### 4.3 短帧处理

命令帧可以短于 8 字节：接收端会把 DLC 之后的字节**清零**，因此：

- `0x02`、`0x15` 可以只发 DLC=0；
- `0x11`~`0x14`/`0x16` 若 DLC < 5，则 `data[4]` 视为 0（**不落盘**）；
- 上游是复用上一帧的 `RxData` 缓冲，短帧会读到残留数据 —— 本移植有意改掉。

### 4.4 与上游的行为差异

| 项 | 上游 | 本移植 | 原因 |
|---|---|---|---|
| 命令执行上下文 | CAN 接收中断内 | `can` 线程（优先级 14） | 避免与 20 kHz 环/100 Hz 线程争用字段 |
| 收发缓冲 | `*(float*)RxData` 强转 | `memcpy` | 未对齐访问 + 严格别名 UB |
| 发送失败 | `Error_Handler()` 停机 | 计数 `txfail` | 后台线程不应停机 |
| Flash 落盘 | 置标志后立即写 | 等电机停机再写 | 擦除会让 20 kHz 中断断供 20~40 ms |
| `off`/`brake` 后收命令 | 上游无 `soft_disable` 概念 | `0x01/0x03~0x07` 自动清标志 | 否则命令"生效但电机不动" |

## 5. 与 msh 命令的对应

| msh | CAN |
|---|---|
| `xdrv on` | `0x01`（data = 1，但模式固定为速度） |
| `xdrv off` | `0x01`（data ≠ 1） |
| `xdrv cur <mA>` | `0x03`（单位 A） |
| `xdrv vel <milli-rev/s>` | `0x04`（单位 r/s） |
| `xdrv pos <milli-rev>` | `0x05` / `0x07`（单位 r） |
| `xdrv cali` | `0x02` |
| `xdrv home` | `0x15` |
| `xdrv save` | `0x11`~`0x1B` 的 `data[4]=1` |
| `xdrv node <id>` | `0x11` |
| `xdrv status` | `0x21`~`0x24` |
| `xdrv restore` | `0x7E` + 重新上电 |

> 注意单位不同：msh 用千分之一（milli-rev、mA、milli-rev/s），CAN 用 **r/s、A** 等物理单位（浮点）。

## 6. 诊断

`xdrv status` 末行：

```
can     : rx=1234 cmd=1200 other=34 drop=0 txfail=0
```

| 字段 | 含义 | 异常判读 |
|---|---|---|
| `rx` | 中断收到的帧数（含过滤掉的） | 不增长 = 没接线/位时序不对/无终端电阻 |
| `cmd` | 实际执行的命令数 | 远小于 `rx` 且 `other` 很大 → 节点号不匹配 |
| `other` | 节点号不匹配而忽略 | 持续增长说明总线上有别的节点号 |
| `drop` | 8 深队列满被丢 | 主机发太快，或 `can` 线程被长时间抢占 |
| `txfail` | 应答发不出去 | 总线上没有第二个节点 ACK（单板裸测正常现象）、未接收发器 |

实现细节：接收中断（优先级 3）只做 `HAL_CAN_GetRxMessage` → 8 帧环形队列 →
`rt_sem_release`；命令在 `can` 线程执行，改 controller 的几行在临界区内，
应答发送在临界区外（`HAL_CAN_AddTxMessage` 依赖 `HAL_GetTick`，关中断时会死等）。

## 7. 主机端建议

1. 接收过滤放行 `base | 0x21..0x24`（或全通，靠 ID 匹配）。
2. 单板调试时用广播（node 0），多板时先 `xdrv node` 或 `0x11` 设好各自节点号。
3. 位置/速度命令给浮点即可，驱动器内部换算成 51200 steps/圈。
4. 需要"到位"握手：用 `0x07`（总是应答）或 `0x05` + `data[4]=1`，读应答的 `data[4]`。
5. 换板后必须重做校准（`xdrv cali`）与零点（`xdrv home`）—— 校准表在 MCU Flash 里。
